## 1. 项目概述

### 1.1 业务定位

本系统面向 **2人规模的工业品贸易小公司**，提供进销存全流程管理，覆盖：
- 商品管理（分类、规格、单位、价格体系）
- 库存管理（多仓库、库存流水、调拨、预警）
- 销售管理（标准销售单、快速收银、退货）
- 客户管理（专属定价、对账单）
- 报表分析（销售趋势、利润、库存周转、滞销预警、异常检测）

### 1.2 核心设计理念

| 设计维度 | 选择 | 理由 |
|---------|------|------|
| 架构模式 | 纯前端 + Supabase BaaS | 2人团队无需自建后端，Supabase 提供数据库+认证+实时推送 |
| 部署策略 | GitHub Pages + PWA + Tauri | 零运维成本，三端覆盖（Web/移动/桌面） |
| 状态管理 | Pinia + Vue Composables | 轻量级，适合中小型应用 |
| UI 框架 | Tailwind CSS + 自定义组件 | 高度定制化，统一设计语言 |

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐

└──────┬──────┘     └──────┬──────┘     └──────┬──────┘
       │                   │                   │
       ▼                   ▼                   ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  products   │────▶│   stocks    │◀────│ stock_lots  │
│  (商品)     │     │  (库存)     │     │  (批次)     │
└──────┬──────┘     └─────────────┘     └─────────────┘
       │
       ▼
┌─────────────┐     ┌─────────────┐
│  customers  │────▶│customer_    │

│       │                                   │
│       ▼                                   │

```

### 3.2 数据表清单

| 表名 | 说明 | 核心字段 |
|------|------|---------|
| `categories` | 商品分类 | id, name, sort_order |
| `warehouses` | 仓库 | id, name, location, is_default |
| `products` | 商品 | id, name, category_id, unit, reference_price, cost_price, min_stock, is_active |
| `customers` | 客户 | id, name, type, contact_person, phone, address, credit_limit |
| `customer_prices` | 客户专属定价 | customer_id + product_id (复合主键), price |
| `stocks` | 库存 | warehouse_id + product_id (唯一约束), quantity |
| `stock_lots` | 批次库存 | product_id, warehouse_id, supplier_id, quantity, unit_cost, is_estimated |
| `stock_transactions` | 库存流水 | warehouse_id, product_id, type, quantity, unit_cost, ref_type, ref_id |
| `sales_orders` | 销售单 | order_no (自动生成), customer_id, warehouse_id, status, total_amount, paid_amount |
| `sales_order_items` | 销售明细 | sales_order_id, product_id, quantity, unit_price, cost_price, line_total (生成列) |
| `payment_records` | 收款记录 | sales_order_id, amount, payment_method, type |
| `sales_return_orders` | 退货单 | order_no, customer_id, warehouse_id, status, total_amount |
| `sales_return_items` | 退货明细 | return_order_id, product_id, quantity, unit_price, line_total |
| `stock_transfers` | 库存调拨 | order_no, from_warehouse_id, to_warehouse_id, status |
| `stock_transfer_items` | 调拨明细 | transfer_id, product_id, quantity |

### 3.3 数据库函数 (RPC)

| 函数名 | 用途 | 参数 |
|--------|------|------|
| `generate_order_no(prefix)` | 自动生成订单号 (格式: `{prefix}-{YYYYMMDD}-{0001}`) | prefix: 'SO'/'SR'/'TF' |
| `update_updated_at()` | 更新时间戳触发器 | - |
| `set_order_no()` | INSERT 前自动生成订单号 | - |
| `complete_sales_order(p_order_id)` | 完成销售单：扣减库存 + 记录流水 + 更新应收 | p_order_id |
| `complete_sales_order_mw(p_order_id)` | 多仓库模式完成销售单 | p_order_id |
| `complete_sales_return(p_return_id)` | 完成退货：恢复库存 + 记录流水 | p_return_id |
| `reverse_sales_order(p_order_id)` | 逆向操作：恢复库存 + 恢复应收 | p_order_id |
| `get_monthly_sales_trend(p_start_date)` | 月度销售趋势统计 | p_start_date |
| `get_stock_transactions_by_date(...)` | 按日期汇总库存流水 | 多参数可选 |
| `stock_in_with_lot(...)` | 批次入库 | product_id, warehouse_id, quantity, unit_cost 等 |
| `update_lot_cost(p_lot_id, p_new_cost)` | 更新批次成本 | p_lot_id, p_new_cost |
| `recalc_product_cost(p_product_id)` | 重新计算商品成本 | p_product_id |

### 3.4 订单号生成规则

```
销售单: SO-20260620-0001
退货单: SR-20260620-0001
调拨单: TF-20260620-0001

规则：前缀-日期-4位序号（当天自增）
```

### 3.5 RLS 安全策略

所有 14 张表均启用了 Row Level Security，策略为 **全员可读写**（适合 2 人小团队）：
```sql
CREATE POLICY "全员可读写" ON <table> FOR ALL USING (true) WITH CHECK (true);
```

### 4.2 鉴权流程

```
用户输入 username + password
    ↓
stores/auth.ts → login(username, password)
    ↓
校验 username === DEFAULT_USERNAME ('huiyou')
    ↓
supabase.auth.signInWithPassword({ email, password })
    ↓
成功 → loggedIn = true → router.push('/dashboard')
失败 → 返回中文错误提示
    ↓
路由守卫 (router/index.ts):
  beforeEach → 检查 supabase.auth.getSession()
  → 无 session 且非 /login → 重定向 /login
  → 有 session → 放行
```

### 4.3 布局系统 (Layout.vue)

- **桌面端**: 可折叠侧边栏 (4rem / 14rem) + 顶部导航栏 + 内容区
- **移动端**: 汉堡菜单 + 滑出式侧边栏
- **页面切换动画**: GSAP 驱动的淡入淡出 + 位移动画
- **Keep-alive**: 最多缓存 10 个页面组件

### 4.4 全局错误处理

```typescript
  const msg = getErrorMessage(err)

}
```

```typescript
// 单次查询获取商品+分类+库存
const { data } = await supabase
  .from('products')
  .select('*, categories!left(name), stocks!left(quantity)', { count: 'exact' })

// 在 JS 端聚合库存
const mapped = data.map(p => ({
  ...p,
  category_name: p.categories?.name ?? null,
  stock_quantity: (p.stocks ?? []).reduce((sum, s) => sum + s.quantity, 0),
}))
```

## 6. 核心业务流程

### 6.1 快速收银流程 (SaleQuick.vue)

```
选择商品 → items[] (购物车)
    ↓
调整数量/单价 → 自动计算 line_total
    ↓
点击"收钱完成" →
  createSalesOrder({ customer_id, warehouse_id, status:'draft', total_amount })
    ↓
成功 → saveSalesOrderItems(order_id, items)
    ↓
成功 → completeSalesOrder(order_id)  // RPC: 扣库存 + 更新应收
    ↓
成功 → 可选: createPayment()  // 记录收款
    ↓
完成 → 清空购物车，Toast 提示
```

**特色功能**:
- 利润率实时显示（绿/黄/红/💀 标记）
- 低于进价警告（💀 图标）
- 支持"收钱完成"和"记账"两种模式
- 搜索式商品选择（支持名称/规格/条码搜索）

### 6.2 标准销售单流程 (SaleForm.vue)

```
填写表单（客户、仓库、备注、是否需要发货）
    ↓
添加商品明细（每行: 商品、数量、单价）
    ↓
保存草稿 → createSalesOrder(status:'draft') + saveSalesOrderItems()
    ↓
完成订单 → completeSalesOrder(id)  // 调用 RPC，不可逆
    ↓
可追加收款 → createPayment({ order_id, amount, method })
    ↓
支持逆向操作 → reverseSalesOrder(id)  // 恢复库存
```

### 6.3 退货流程 (SaleReturnForm.vue)

```
选择原始销售单 → 加载原单明细
    ↓
选择退货商品/数量
    ↓
保存 → createSalesReturn()
    ↓
完成 → completeSalesReturn(id)  // RPC: 恢复库存
```

### 6.4 库存调拨流程

```
选择源仓库 + 目标仓库
    ↓
添加调拨商品/数量
    ↓
完成 → RPC 扣减源仓库库存 + 增加目标仓库库存
```
