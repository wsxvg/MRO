## 二、逐项分析与改进方案

### 问题 1：SaleList 功能过载（严重度：高）

**现状：**
SaleList.vue 一个页面承担了 6 个职责：
- 待发货订单列表 + 确认完成
- 已完成订单列表 + 状态筛选
- 退货操作（弹窗选商品 → 创建退货单 → 自动完成）
- 撤回订单（恢复库存 + 删除订单）
- 打印送货单 / 报价单
- 导出对账单

所有操作混在同一个 Tab 页面里，用户需要理解"待发货"和"已完成"的区别，还要知道退货、撤回、打印分别在哪里触发。

**改进方案：**

**方案 A：拆分为独立页面（推荐）**

```
销售管理（/sales）
├── 销售单列表（只看 + 筛选 + 打印）
├── 待发货列表（独立页面，操作更清晰）
└── 退货管理（独立页面，从这里发起退货）

打印功能统一放到销售单详情页（SaleForm）
```

优点：每个页面职责单一，用户不需要理解复杂的状态流转。
缺点：页面数量增加，侧边栏需要调整。

**方案 B：保留单页，优化交互**

- 用更醒目的 Tab 设计区分"待发货"和"已完成"
- 退货操作改为独立入口（侧边栏加"退货管理"）
- 撤回操作加二次确认弹窗（替换 window.confirm）
- 打印按钮统一放到订单详情页

优点：改动最小。
缺点：页面仍然复杂。

### 问题 2：Dashboard 信息过载（严重度：高）

**现状：**
仪表盘一页展示了 11 个区块：

```
KPI 卡片（4 个）
低库存预警
销售趋势图
最近订单
待发货
待到货
未收款客户
热销 TOP 10（数量）
热销 TOP 10（销售额）
库存分类饼图
异常预警
滞销商品
```

所有信息平铺展示，没有优先级区分。新用户打开首页会被信息淹没。

**改进方案：**

**方案 A：分区折叠（推荐）**

将 11 个区块分为 3 个区域，默认只展开核心区域：

```
┌─────────────────────────────────────┐
│  核心区（始终显示）                    │
│  KPI 卡片 + 低库存预警 + 销售趋势     │
├─────────────────────────────────────┤
│  待办区（默认展开）                    │
│  待发货 + 待到货 + 未收款客户          │
├─────────────────────────────────────┤
│  分析区（默认折叠）                    │
│  热销排行 + 库存饼图 + 异常 + 滞销     │
└─────────────────────────────────────┘
```

**方案 B：可自定义看板**

用户可以拖拽排序、显示/隐藏区块。类似 Notion 的 Block 系统。

优点：灵活度高。
缺点：开发成本高，2 人团队可能不需要这么复杂。

### 问题 3：页面标题不一致（严重度：中）

**现状：**
- 侧边栏显示"采购管理"
- 页面标题显示"进货入库"
- 路由路径是 `/stock/in`

三个地方用了三个不同的名字，用户会困惑。

**改进方案：**

统一命名为"采购管理"：

| 位置 | 改前 | 改后 |
|------|------|------|
| 侧边栏 | 采购管理 | 采购管理（不变） |
| 页面标题 | 进货入库 | 采购管理 |
| 路由路径 | /stock/in | /stock/in（不变，URL 不影响用户感知） |
| 按钮文字 | 📥 进货 | 📥 新建采购 |

### 问题 4：设置层级太深（严重度：中）

**现状：**
用户想找"供应商管理"需要：侧边栏 → 系统设置 → 供应商管理，3 次点击。而"分类管理"和"单位管理"虽然在设置里，但其实是高频操作（新增商品时需要先创建分类/单位）。

**改进方案：**

**方案 A：提升高频设置到侧边栏**

```
侧边栏导航：
├── 仪表板
├── 库存查询
├── 采购管理
├── 销售管理
├── 客户管理
├── 分类管理        ← 从设置中提升
├── 供应商管理      ← 从设置中提升
└── 系统设置        ← 只保留仓库、单位、数据导入导出
```

**方案 B：设置页面加快捷入口**

在设置页面顶部加"常用设置"区域：

```
常用设置：[分类管理] [供应商管理] [单位管理]

仓库管理 | 批次管理 | 数据导入导出
```

### 问题 5：打印入口分散（严重度：中）

**现状：**

| 打印类型 | 可用位置 | 不可用位置 |
|---------|---------|-----------|
| 送货单 | SaleList（订单列表） | SaleForm（订单详情） |
| 报价单 | SaleList（订单列表） | SaleForm（订单详情） |
| 销售单 | SaleForm（订单详情） | SaleList（订单列表） |
| 对账单 | CustomerStatement | - |

用户需要知道"在哪个页面才能打印哪种单据"。

**改进方案：**

统一在订单详情页（SaleForm）提供所有打印入口：

```
SaleForm 页面操作区：
[ 打印销售单 ] [ 打印送货单 ] [ 打印报价单 ] [ 导出 Excel ]
```

SaleList 列表页只保留"查看"按钮，不直接提供打印。

### 问题 6：确认操作风格不一致（严重度：低）

**现状：**
- 大部分地方用 `ConfirmDialog` 组件（自定义弹窗）
- SaleList 撤回订单用 `window.confirm()`（浏览器原生弹窗）

两种确认弹窗视觉风格完全不同。

**改进方案：**

统一使用 `ConfirmDialog` 组件，替换所有 `window.confirm()` 调用。同时给 `ConfirmDialog` 加一个 `danger` 模式（红色按钮），用于撤回、删除等危险操作。

---

### 问题 7：无面包屑导航（严重度：低）

**现状：**
深层页面（如 `/products/123`、`/customers/456/pricing`、`/settings/warehouses/789/stock`）没有面包屑，用户不知道自己在哪一层级。

**改进方案：**

在 Layout 的内容区顶部加面包屑：

```
首页 > 客户管理 > 客户专属价格
```

实现方式：根据 `route.matched` 自动生成。
